# Masking Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close four deferred minors from #26 in the skeleton's `Redaction`: give it lasting runtime tests, mask a value with no closing quote instead of leaving it, make the `esc` regex linear, and stop pass 1 of `MaskZip` from decompressing non-trace entries.

**Architecture:** `Harness.Tools.Tests` gets a build target that renders `templates/framework/src/__Name__.Framework/Utils/Redaction.cs` into `obj/` (with `{{Name}}` replaced) and compiles it into the test assembly, so xUnit tests call the real template code. The three behaviour fixes are then TDD against those tests. Everything stays inside `Redaction.cs`, and no public signature changes.

**Tech Stack:** C# / net10.0, `[GeneratedRegex]`, `System.IO.Compression`, xUnit v3 on MTP, MSBuild.

**Spec:** the deferred minors in the 2026-11-21 handoff (memory `latest-handoff.md`, "New deferred minors"), as chosen in session: items 2–5. Item 1 (over-masking on malformed nested input) is dropped on purpose, because over-masking is the safe way to fail.

## Global Constraints

- Branch `harness/masking-hardening` off `main` (`bb59e0b`). **Never commit.** At the end, suggest a commit message and PR description.
- Warnings are errors (`tools/Directory.Build.props`). Test-first for every behaviour change.
- No public API change to `Redaction`: `Remember(string)`, `Mask(string) -> string`, `MaskZip(string)`.
- Facts come from spikes: the claim that typed-password snapshots live only in `*.trace` entries goes into `docs/framework-matrix.md` only after the Task 4 spike shows it.
- Template code stays framework-neutral and free of `Console.`, `.Result` and `.Wait()` (the existing pins in `ScaffolderTests.RealTemplates_Redaction_MasksTheSpikedForms`).
- Remembered values are global static state, and xUnit runs test classes in parallel. Every test uses its own distinct secret strings.

## Review Focus

1. **A raw newline inside a JSON value.** People expect the text before the newline to be hidden. It is masked up to the line end (Task 2, `Mask_RawNewlineInValue_MasksToEndOfLine`).
2. **CRLF text.** People expect the `\r` to be kept, so the line ending is not damaged (Task 2, `Mask_CrLfInValue_KeepsTheLineEnding`).
3. **A secret field with no closing quote at the end of the text, as in a truncated log.** People expect the tail to be masked (Task 2, `Mask_UnclosedValueAtEnd_MasksToEnd`).
4. **A valid masked `trace.trace` line must still parse.** The new fallback must not change any well-formed line (Task 2, `MaskZip_WellFormedTraceLines_StillParse`).
5. **A literal backslash right before a quoted secret name,** such as `C:\"password":"x"`. Today the regex retries with no backslashes and masks it. A plain `(?<!\\)` lookbehind would lose that and leak the value, so the fix keeps a zero-backslash branch (Task 3, `Mask_BackslashBeforeFieldName_StillMasks`).

### Task 1: Compile the template into the tests and pin today's behaviour

**Files:**

**Interfaces:**
- Produces: the type `HarnessTemplates.Framework.Utils.Redaction`, compiled into the test assembly, and the test class `Harness.Tools.Tests.Templates.RedactionTests`. Later tasks add facts to it. It has a private helper `static string Zip(string dir, params (string Name, byte[] Bytes)[] entries) -> string path` and `static string Entry(string zipPath, string name) -> string`.

- [ ] **Step 1: Add the render target to the csproj.** This is the non-obvious part. `WriteLinesToFile` splits on `;`, so the content must be escaped. `// <auto-generated/>` keeps the repo's analyzers off template code, which the consumer's settings already govern. `#nullable enable` restores the nullable context that generated code loses.

```xml
<PropertyGroup>
  <RedactionTemplate>$(MSBuildThisFileDirectory)..\..\templates\framework\src\__Name__.Framework\Utils\Redaction.cs</RedactionTemplate>
  <RedactionRendered>$(IntermediateOutputPath)Templates\Redaction.g.cs</RedactionRendered>
</PropertyGroup>

<Target Name="RenderRedactionTemplate" BeforeTargets="BeforeCompile;CoreCompile" Inputs="$(RedactionTemplate)" Outputs="$(RedactionRendered)">
  <PropertyGroup>
    <_RedactionText>$([System.IO.File]::ReadAllText('$(RedactionTemplate)').Replace('{{Name}}', 'HarnessTemplates'))</_RedactionText>
  </PropertyGroup>
  <WriteLinesToFile File="$(RedactionRendered)" Lines="// &lt;auto-generated/&gt;;#nullable enable;$([MSBuild]::Escape('$(_RedactionText)'))" Overwrite="true" WriteOnlyWhenDifferent="true" />
</Target>

<Target Name="IncludeRedactionTemplate" BeforeTargets="BeforeCompile;CoreCompile" DependsOnTargets="RenderRedactionTemplate">
  <ItemGroup>
    <Compile Include="$(RedactionRendered)" />
    <FileWrites Include="$(RedactionRendered)" />
  </ItemGroup>
</Target>
```

The include runs on every build, and the render runs only when the template changes. If the build still reports analyzer or CS diagnostics on `Redaction.g.cs`, check first whether `templates/build/` settings flag the same thing. If they do, fix the template. If they don't, add only that ID under `[**/Templates/Redaction.g.cs]` in a new `tools/Harness.Tools.Tests/.editorconfig`.

### Task 3: The `esc` regex starts only at the beginning of a backslash run

**Files:**
- Modify: `templates/framework/src/__Name__.Framework/Utils/Redaction.cs:287-289` (`JsonField`)
- Test: `tools/Harness.Tools.Tests/Templates/RedactionTests.cs`

**Interfaces:**
- Consumes: `RedactionTests`.
- Produces: nothing new.

- [ ] **Step 1: Write the failing tests.**
  - `Mask_LongBackslashRun_IsLinear`: the input is `new string('\\', 100_000) + "x"`. Time `Mask` with a `Stopwatch`. Assert that it takes under 5 seconds, and that the result equals the input.
  - `Mask_BackslashBeforeFieldName_StillMasks`: the input is the literal characters `C:\"password":"x-h"`, and the result equals `C:\"password":"***"`. It passes today, because the regex retries at the quote with an empty `esc`. It is a guard, so the fix must keep it green.

- [ ] **Step 2: Run the tests.** Use the Task 1 filter command. `Mask_LongBackslashRun_IsLinear` should fail on time, because each start inside the run rescans the run. If it passes in under 5 s on this machine, raise the count to 300_000 and record both timings.

- [ ] **Step 3: Change the regex.** Replace `(?<esc>\\*)` with `(?<esc>(?<!\\)\\+|)`, giving `@"(?<esc>(?<!\\)\\+|)""(?:" + SecretNames + …`. `esc` is now either a whole run, tried only where the run starts, or empty, tried only right before a quote. That makes every start position O(1) except a run's first, which is O(run) once. Update the comment.

- [ ] **Step 4: Run the tests.** Run all `RedactionTests`. They should pass, with the long-run fact in milliseconds.
